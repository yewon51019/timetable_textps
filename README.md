# 시간표 캡처 → 요일별 첫 수업 시작 시각 추출

대중교통 알리미 AI (PRD v0.1) 의 **FR-01 시간표 인식 및 요일별 첫 수업 시각 추출** 실험 코드입니다.

| 파일 | 내용 |
|---|---|
| `baseline_gemini.py` | Gemini가 작성한 원본 코드 (비교용, GPU 옵션만 끔) |
| `timetable_first_class.py` | 개선 버전 |
| `evaluate.py` | 정답과 비교 + 해상도 변경(0.6배·1.5배) 견고성 테스트 |
| `results/first_class_times.md` | **요일별 첫 수업 시각 결과표** |
| `results/timetable_N_result.png` | 이미지별 검출 시각화 |
| `results/evaluation.md` | 요일별 정답 / 원본 / 개선 비교 |

```bash
pip install -r requirements.txt
python baseline_gemini.py          # 원본 → results/baseline.json
python timetable_first_class.py    # 개선 → results/improved.json, *_result.png
python evaluate.py                 # 비교표 → results/evaluation.md
```

## 결과

| 방법 | 요일 단위 정답률 (25개 요일) |
|---|---|
| Gemini 원본 | **15/25 = 60%** |
| 개선 버전 | **25/25 = 100%** (0.6배·1.5배 크기로 바꿔도 100%) |

## 원본 코드가 틀린 이유

| # | 문제 | 실제로 생긴 오류 |
|---|---|---|
| 1 | **표 범위를 9~21시로 고정**하고 이미지 전체 높이를 12등분 | 9~18시 표(1,2,3,5번)에서 1시간 칸이 실제의 약 3/4로 계산되어 시각이 밀림. 2번 화요일 13시 → 14시 |
| 2 | **이미지 전체 = 표**로 가정 | 왼쪽 시간축 여백·아래 요일 라벨 영역까지 표로 계산해 좌표가 어긋남 |
| 3 | **글자 중심 y**로 시각을 계산 | 시간을 결정하는 건 수업 칸의 **위쪽 경계**인데, 글자 중심을 써서 늦게 나옴 (2번 수요일 15시 → 17시) |
| 4 | OCR로 읽은 **모든 글자**를 수업으로 취급 | 시간축 숫자 `9`, `10`…은 월요일 수업으로, 아래쪽 요일 라벨 `목`, `금`은 20시 수업으로 잡힘 → 공강이 공강으로 안 나옴 (3번 금, 5번 목 → 20시) |
| 5 | 글자 **좌표로 요일 결정** | 칸 밖으로 넘친 과목명(3번 월요일 `인간컴퓨터상호작용론`)이 옆 요일로 잡힐 위험 |
| 6 | `int()`로 버림 | 10:30 같은 분 단위 시작은 표현 불가 |

즉 원본은 "OCR이 좋으면 잘 될 것"이라는 접근이지만, 실제 문제는 **OCR이 아니라 좌표 해석**에 있었습니다. 1번 이미지가 다 맞은 건 모든 요일이 9시라서 생긴 우연입니다.

## 개선 방법과 개념

핵심은 **역할 분리**: *수업이 어디 있는지*는 색으로, *그 위치가 몇 시인지*는 시간축 숫자로 알아냅니다.

```
이미지 ─┬─ ① 정규화 (RGBA→RGB, 라이트/다크 판별)
        ├─ ② 격자선 검출 → 표 영역 + 요일 열 5개
        ├─ ③ OCR(시간축 숫자만) → y = a·시 + b 직선 맞춤
        ├─ ④ 색 분할 → 수업 칸 사각형
        └─ ⑤ 요일별 가장 위 칸의 위쪽 경계 y → 시각
```

### ① 이미지 정규화
에브리타임 캡처는 RGBA(투명 채널 포함) PNG입니다. 흰 배경으로 합성해 3채널로 맞추고, 테두리 픽셀의 중앙값(median)으로 **라이트/다크 테마**를 판별합니다. 원본처럼 CLAHE(국소 대비 향상)로 흑백 변환하면 오히려 **수업 칸의 색 정보가 사라지므로** 쓰지 않습니다.

### ② 격자선 검출 — 투영(projection)
격자선은 **채도가 거의 0인 회색**입니다. 회색 픽셀만 마스크로 만든 뒤 열(column)마다 개수를 세면(세로 투영), 세로선 위치에서 값이 높이 솟습니다. 가장 왼쪽·오른쪽 세로선이 표의 좌우 경계, 그 사이 6개 선이 요일 5칸입니다. 이미지 너비가 1184px이든 1160px이든(4번) 자동으로 맞춰집니다.

### ③ 시간축 보정 — OCR + 선형 회귀
표 **왼쪽 바깥**에서 읽힌 숫자만 시간 라벨로 씁니다(칸 안의 `602`, `101` 같은 강의실 번호 배제). 라벨 (y좌표, 시) 쌍들로 `y = a·시 + b`를 **최소제곱 직선 맞춤(np.polyfit)** 합니다.
- `a` = 1시간의 픽셀 높이, `b` = 0시의 가상 y좌표
- 9~18시 표든 9~21시 표든, 해상도가 달라도 이미지마다 새로 계산 → 원본의 "9~21시 고정" 문제 해결
- 라벨 하나쯤 잘못 읽어도 잔차가 큰 점을 빼고 다시 맞춤(간이 이상치 제거). 실제로 4번은 `9`를 못 읽었지만 나머지 12개로 정확히 맞춤
- 라벨이 3개 미만이면 `확인 필요` 상태 (PRD AC-01-03)

### ④ 수업 칸 검출 — HSV 색 분할 + 연결 요소
**HSV**는 색을 색상(H)·채도(S)·밝기(V)로 나눈 색 공간입니다. 배경(흰/검정)과 격자(회색)는 채도가 낮고, 수업 칸은 파스텔이지만 채도가 높습니다. 그래서 `S > 40` 이면 수업 칸으로 봅니다 — **테마와 무관**하게 동작합니다.
- 이웃 요일 칸끼리 붙지 않도록 세로선 위치를 끊고, **모폴로지 열림(opening)** 으로 잡티 제거
- **연결 요소(connected components)** 로 덩어리마다 외곽 사각형을 구함. 흰 글자는 사각형 안의 구멍일 뿐이라 영향 없음
- 사각형 중심 x가 속한 열 = 요일 → 넘친 글자가 있어도 요일이 바뀌지 않음

### ⑤ 첫 수업 시각
요일마다 가장 위에 있는 칸의 **위쪽 경계 y**를 `시 = (y − b) / a`로 바꾸고 5분 단위로 반올림합니다. 칸이 없으면 `공강`.
OCR로 읽은 과목명은 칸에 붙여 참고용으로만 표시합니다(PRD: "과목 글자는 수업 칸을 찾는 데만 활용"). EasyOCR의 `width_ths`를 낮춰 옆 칸 글자가 한 줄로 합쳐지지 않게 했습니다.

## 한계와 다음 단계
- 과목명 OCR은 아직 오인식이 있음(`딥러닝`→`덥러님`). 시각 계산에는 쓰지 않으므로 결과엔 영향 없음. PRD대로 PaddleOCR로 바꾸면 한글 정확도가 더 좋아질 것.
- 아주 연한 색(채도 40 이하) 테마나 배경 이미지 테마는 아직 검증 안 됨 → 6주차 파일럿 데이터로 임계값 점검 필요.
- 평가 이미지 5장(25개 요일)은 작으므로 PRD 목표(90%)를 확정하려면 더 많은 캡처로 재측정 필요.
